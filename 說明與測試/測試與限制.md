# DIAG-2.0.0 測試與限制

## 已執行

- Node.js 22.16.0：45 項解析／來源關聯／匯出／隱私／大小限制單元測試全數通過。
- Chromium + Playwright：17 項記憶體載入環境 UI／原生 Worker 檢查全數通過。
- 使用 44,780 行、24.86 MiB 合成資料完成掃描；測得耗時詳見 JSON 結果。
  這不是你的實際檔案，也不是 iPhone 效能承諾。
- 主畫面 390 × 844 版型未見水平溢出；附截圖含合成資料，不是真實手機配置。
- 在程式與 Worker 已載入後，斷網選檔及掃描成功。
- 分析與匯出過程未產生 HTTP(S) 上傳請求。匯出 JSON 與預覽逐字相同。
- CSP 的 connect-src 'none' 以獨立測試頁驗證阻擋連線；form-action 'none' 僅核對指令存在。

## 沒有執行／不能據此宣稱的項目

- 本容器 Chromium 的管理政策禁止網站導覽。實際 HTTP/HTTPS 網站導覽測試被阻擋。
  改用記憶體載入相同 HTML/CSS/UI/Core 與原生 Blob Worker，只替換資產載入方式；
  因此這不是完整的 GitHub Pages 端到端驗收。
- 沒有 iPhone Safari 實機、沒有使用者原 Analytics 檔案。
- 沒有驗證任何私有硬體代碼能對應特定供應商。
- 沒有資安機構稽核，沒有保證瀏覽器或已安裝的上層 Service Worker 永遠可信。

## 可重跑的測試

在本資料夾的上一層執行：

```sh
node --test 說明與測試/test-core.cjs
```

瀏覽器測試依賴 Python Playwright 與 Chromium。`test-browser.py` 是正常的
HTTP 資產載入測試腳本（本環境因管理政策未跑通），需先在套件根目錄啟動：

```sh
python -m http.server 8891 --bind 127.0.0.1
python 說明與測試/test-browser.py
```

`test-browser-memory.py` 是此次實際執行的替代載入測試。需要系統 Chromium
位於 `/usr/bin/chromium`；其他環境請調整測試程式的 executable_path。
這些指令是本機測試用，不會修改 GitHub。

## 測試資料原則

測試程式只使用人工合成數值和通用欄位名稱；不打包使用者的原始 Analytics
或上傳的完整 JSON。16 個優先欄位取自先前 DIAG-1 的欄位盤點，測試不表示
已還原或驗證這些欄位在真實檔案中的值。

## 正式回饋需包含

頁面版本 DIAG-2.0.0、完整掃描是否完成、限制計數、來源標記，以及使用者
檢查後自願匯出的候選值摘要。未知來源需保留，不得為了增加顯示項目而假定
所有資料都屬於 iPhone。
